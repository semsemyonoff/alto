# Repository Guidelines

## Project Structure & Module Organization
`cmd/alto` contains the main entrypoint, config parsing, and startup wiring. Core application code lives under `internal/`: `db` for SQLite access, `library` for scanning and `ffprobe` metadata, `server` for HTTP handlers and HTMX/SSE flows, and `transcode` for ffmpeg job execution. Runtime templates live in `web/templates`; disk-served static assets in `web/static` (including the Vite build output at `web/static/dist`, which is gitignored and built, not checked in). The frontend toolchain (Vite + TypeScript + Alpine.js islands + PostCSS) lives in `web/frontend` — `src/main.ts` is the entry point, `src/styles/` holds the ported design-system CSS, and per-feature TS modules (`queue.ts`, `dock.ts`, `libmenu.ts`, `treesearch.ts`, `ui/resizer.ts`) pair with Vitest specs. Top-level `assets/` and `static/` are documentation and branding assets, not application runtime code. Keep long-form planning notes in `docs/plans` (completed plans move to `docs/plans/completed/`); repository automation state under `.ralphex/` is not product code.

## Build, Test, and Development Commands
Use the `Makefile` targets first:

- `make build` builds the `alto` binary from `./cmd/alto`; depends on `frontend-build` so the Vite bundle is always current.
- `make frontend-build` runs `npm ci && npm run build` in `web/frontend`, producing `web/static/dist` plus its manifest.
- `make dev` runs the Vite dev server and `go run ./cmd/alto` together (`ALTO_VITE_DEV=1`) for local frontend development with HMR.
- `make test` runs `go test ./...` across all packages.
- `make test-race` runs the same suite under the race detector (`CGO_ENABLED=1 go test -race ./...`); it needs a C compiler, which the Alpine dev image does not ship.
- `make lint` runs `golangci-lint run`.
- `ALTO_LIBRARIES="Music:/path/to/music" make run` starts the app locally (serves the last built frontend bundle, not Vite HMR — use `make dev` for that).
- `make docker-build` builds a local Docker image as `alto:latest`.
- `make image-build` builds and pushes a multi-arch image using `build.sh`; defaults are `semsemyonoff/alto:latest` and `linux/amd64,linux/arm64`.
- `docker compose up -d` runs the production/operator stack (`docker-compose.yml`), which pulls a published image and reads `.env` (`cp .env.example .env` first). For a container built from the working tree, use `make docker-build` or `make release-local`. Release plumbing lives in `VERSION`, `CHANGELOG.md`, and the `.forgejo/`/`.github/` workflows.
- Inside `web/frontend`: `npm run build`, `npm run dev`, and `npm run test` (Vitest) drive the frontend directly.

Local development expects Go `1.26.2`, Node.js (for the `web/frontend` Vite/TypeScript toolchain), plus `ffmpeg` and `ffprobe` on `PATH`. Docker is required only for container workflows.

## Coding Style & Naming Conventions
Follow standard Go formatting with `gofmt`; do not hand-format Go files to match the global EditorConfig spacing. Use lower-case package names, `CamelCase` for exported identifiers, and descriptive handler/test names such as `TestHandleTree_InvalidID`. For non-Go files, `.editorconfig` sets 4-space indentation by default, 2 spaces for `yml`, `yaml`, `json`, and `sh`, and tabs for `Makefile`.

## Testing Guidelines
Keep tests next to the code they cover in `*_test.go` files. Prefer table-driven tests and `t.TempDir()` or in-memory SQLite for isolated filesystem and DB coverage. When changing env parsing or startup behavior, extend tests under `cmd/alto`; when changing HTTP or UI behavior, extend the server tests in `internal/server`; when changing scanning or transcoding logic, add cases under `internal/library` or `internal/transcode`. Run `make test` and `make lint` before opening a PR.

Scanner-specific traps: probing is concurrent, so run `make test-race` (`go test -race ./...`) after touching `internal/library` — the race detector needs cgo, which the Alpine dev image does not provide (`CGO_ENABLED=0`, no C toolchain), so run it on a host with a C compiler or add `gcc`/`musl-dev` to the image first. A test that must trigger a re-probe has to change the file's size **or** call `os.Chtimes` with an explicitly distant timestamp: the cache key is `(size, mtime)` at nanosecond resolution, and a bare rewrite of a small fixture can land in the same window and pass falsely. Write-count assertions use `openCountingTestDB` (file-backed DB plus `AFTER INSERT`/`AFTER UPDATE` triggers on a second connection) — an `ON CONFLICT DO UPDATE` upsert preserves the `rowid`, so rowid comparisons cannot tell a skipped write from a no-op one.

## Commit & Pull Request Guidelines
Recent history uses Conventional Commit prefixes, mainly `feat:` and `fix:`, with imperative summaries like `feat: transcoding API with job management`. Keep commits focused and similarly formatted. PRs should explain behavior changes, note any environment or mount-mode implications, link related issues, and include screenshots for template/CSS/UI changes. List the verification commands you ran in the PR description.

## Configuration Tips
`ALTO_LIBRARIES` is required and uses `name:path` pairs such as `Music:/music`. Library names must match `[a-zA-Z0-9_-]`, and library names and paths must be unique. `ALTO_OUTPUT_DIR` defaults to `/out`; if you point it inside a library root, the app will warn and exclude that directory from scans. `ALTO_CACHE_DIR` should stay outside library mounts. Read-only mounts are safe only for shared `/out` mode; local `.alto-out/` and replace mode require writable library mounts. `ALTO_TRANSCODE_WORKERS` sets the bounded transcode worker-pool size (default `1`, minimum `1`); jobs beyond capacity sit `queued` until a worker frees up. `ALTO_SCAN_ON_START` (default `true`) controls the startup re-index; since scanning is incremental a restart normally only walks and `stat`s the tree, so set it to `false` only to skip that walk on very large or slow mounts, or to keep the one full re-probe after an upgrade out of boot — `POST /api/scan` and the UI re-index button are unaffected. It is parsed with `strconv.ParseBool`, and an unparsable value is a fatal startup error rather than a fallback to the default. `ALTO_SCAN_WORKERS` caps concurrent `ffprobe` processes across all libraries during a scan; `0` (the default) resolves to `library.DefaultScanWorkers()` = `min(4, NumCPU)`, and negatives clamp to `0` rather than `1`. Scanning is incremental: `tracks.mtime` (Unix nanoseconds) and `tracks.size` are the cache key, so a file whose `(size, mtime)` matches its indexed row is reused without probing, and a stored `mtime = 0` (migration backfill, failed probe, or a file that changed mid-scan) always forces a re-probe.

## Transcode Queue API
Transcode jobs run through a bounded worker pool with `queued`/`running`/`done`/`failed`/`canceled` states. `GET /api/jobs` lists all jobs (queue order); `GET /api/jobs/events` is the global SSE stream the queue UI subscribes to; `POST /api/jobs/{id}/cancel` cancels a queued or running job. `GET /api/transcode/{jobID}/log` still serves per-job logs, but the old per-job `GET /api/transcode/{jobID}/progress` SSE endpoint has been retired in favor of the global `/api/jobs/events` stream.

`GET /api/tree/{libraryID}/search?q=` returns a flat, library-scoped, case-insensitive list of matching directories (backed by `db.GetDirectorySearch`, paired with `web/frontend/src/treesearch.ts`).

### Error envelope
Every JSON endpoint reports failures through `writeAPIError` (`handlers_api.go`) as `{"error", "code", …}` — the `apiErrorDTO` struct with a custom `MarshalJSON` that flattens an optional `map[string]any` of context, writing `error`/`code` last so context can never clobber them. `code` is the contract; the message is human-readable prose that may change. The constants live in one block in `handlers_api.go` (`codeInvalidRequest` … `codeInternalError`): `invalid_request`, `path_forbidden`, `path_not_found`, `library_not_found`, `not_indexed`, `no_tracks`, `mixed_directory`, `no_lossless_tracks`, `unknown_file`, `lossy_source_selected`, `output_dir_not_configured`, `output_name_conflict`, `copy_skipped_not_applicable`, `engine_unavailable`, `job_already_running`, `job_already_finished`, `job_not_found`, `scan_running`, `no_cover`, `internal_error`. `path_not_found` (absent from the filesystem) and `not_indexed` (present but not in the index) are deliberately distinct — collapsing them would make the two-call agent flow below loop on a typo. `WritePathErrorJSON` (`safepath.go`) maps the path sentinels; the text `WritePathError` stays for `handleDirPage`, which serves a browser page. `handleTreeChildren`/`handleTreeSearch` keep `http.Error` — they serve htmx HTML partials, not JSON, and a test pins that exclusion.

**Every new JSON response body is a named DTO struct with `json` tags, never a `map` literal** — a map is invisible to schema-reflection checks. Some legacy bodies (`/api/dir`'s wrapper, `/api/scan`, the job log) are still maps; do not add more.

### Track selection
`POST /api/transcode` takes `skip_lossy` (server-side sugar), `files` (explicit names) and `copy_skipped`. The default — neither selection field — is unchanged: all-lossless transcodes in full, mixed is `422 mixed_directory`. Selection is resolved in the handler (`handlers_transcode.go` + `selection.go`); the engine stays dumb, since `transcode.Job.Files` was already a list. **`files` presence is `req.Files != nil`, not `len(...) > 0`** — JSON decoding yields `nil` for an absent key and an empty non-nil slice for `[]`, and `{"files":[]}` must be `400 invalid_request` rather than falling into the "no selection" path. `files` accepts lossless names only (`422 lossy_source_selected`); it narrows a job, never widens it. `isLosslessCodec` (`handlers_pages.go`) is the single source of truth for lossless/lossy — no second list anywhere. Validation failures are sentinels in `selection.go` matched with `errors.Is`, carrying the offending names on a `fileNamesError` wrapper; `writeSelectionError` maps each to its code and puts the names in the envelope's context.

`copy_skipped` copies the unselected audio verbatim through `transcode.Job.Passthrough`, filled from the same `unselectedTracks` helper that builds the 202 body's `skipped` list. A failed pass-through copy **fails the job** — unlike `copyNonAudioFiles`, which logs and continues for incidental files, these were explicitly requested and a partial album must never report `done`. It is refused with `copy_skipped_not_applicable` for `output_mode: "replace"`.

`outFilename` rewrites the extension, so distinct sources can collapse onto one output name (`01 A.ape` + `01 A.flac` targeting FLAC) and ffmpeg runs with `-y`. One detector in the handler compares the multiset of `outFilename(selected)` ∪ pass-through names before the job starts and answers `422 output_name_conflict`. It applies with no selection at all — that case was a pre-existing silent data loss.

### Job lifecycle and detail
`GET /api/jobs/{id}` returns `jobDetailDTO` (`jobs.go`) — selection, output dir, error text, timestamps, `evicted`. **Do not extend `jobEvent` with any of this**: it is broadcast per ffmpeg progress line to every open tab, so an O(tracks) payload there would go out dozens of times per second per job. Terminal jobs are *tombstoned*, not deleted: `scheduleEviction` → `jm.evict(id)` sets `evicted: true`, which hides the job from `snapshotJobs`/SSE while `GET /api/jobs/{id}` keeps answering with its terminal status, so `404 job_not_found` means "never existed". Tombstones are dropped only past a FIFO bound (`maxEvictedJobs = 256`, oldest first) counted over tombstones alone. `jobManager.start` takes a `jobMeta` so the detail fields are set atomically with registration — a worker can pick the job up the moment it returns.

### Scan endpoints
`Scanner.ScanDir` (`internal/library/scanner.go`) indexes one directory, sharing `indexAudioDir`/`indexParentDir` with the full walk rather than duplicating the cache read, cover resolution and stale-file cleanup. It **never calls `DeleteStaleDirectories`** — with a single path that would delete the rest of the library's index (pinned by a test) — and it leaves an already-indexed ancestor alone, since `UpsertDirectoryWithAudioFlag` would demote a parent that holds audio itself. Exclusions (`ALTO_OUTPUT_DIR`, `.alto` segments) go through `checkScannable` returning `library.ErrDirExcluded`.

`POST /api/scan/dir?path=` runs it synchronously and returns `scanDirResultDTO` (`{directory, tracks}`, built by the same `newDirectoryDTO`/`newTrackDTOs` as `/api/dir`). It serializes against a full scan in **both** directions via `scanState.dirScanning`, held for the whole call — **not** by reusing `scanState.running`, which `subscribe()` consults: `handleScanStatus` blocks until a `complete`/`error` event arrives, so a synchronous run that set `running` without broadcasting would hang every connecting UI client. `subscribe()` deliberately ignores `dirScanning`, and a test pins that `/api/scan/status` still answers `idle` during a single-directory index. `GET /api/scan/state` reports `{running, started_at}` for the full scan only. Together with the `path_not_found`/`not_indexed` split this is the two-call agent flow: `POST /api/scan/dir` then `POST /api/transcode`, no event stream to parse.

`GET /api/presets` serves `presetsDTO` from the same builder that inlines `tc-presets-data` into the `/dir` page (`handlers_meta.go`); a parity test compares both directions, so a preset added to one path and not the other fails.

## Responsive UI State Model
Mobile/tablet layout (`web/frontend/src/styles/responsive.css`, imported last in `index.css`) is driven entirely by classes on `<body>`, toggled from `web/frontend/src/mobile.ts` via document-level event delegation. Because htmx never replaces `<body>`, these classes survive navigation (directory navigation swaps `#content-area`; the sidebar also swaps `#tree-root` on library switch / search / post-scan reload). The four classes are `tree-open` (sidebar drawer), `dock-open` (transcode dock overlay), `has-sel` (a directory with tracks is shown ⇒ show the Transcode FAB), and `queue-open` (queue expanded ⇒ hide the FAB so it can't overlap). `queue-open` bridges Alpine's local `collapsed` state via `x-effect` on the `.queue` section in `base.html`. On every `htmx:afterSwap`/`historyRestore`, `syncSelection` recomputes `has-sel` from the presence of `#tc-dock` in the content area, and clears `dock-open` **only** when the swap actually replaced `#content-area` (a directory navigation swaps out the dock DOM, so a stale overlay must not linger). A `#tree-root`-only swap deliberately leaves an open dock alone so a background scan reload can't slam it shut. The tree-drawer auto-dismiss lives separately in `main.ts`: the `a.tree-label-link` click handler clears `tree-open` so opening a directory closes the drawer. Breakpoints: `≤1023` (shared tablet+mobile), `640–1023` (tablet drawer), `≤639` (mobile bottom-sheet). All rules live behind media queries; the desktop layout is untouched.
